Objects in Javascript

Overview

In most programming languages, an Object is a container. They typically contain "Name:Value" pairs grouped together, called properties. In JavaScript, almost everything is an object. All primitive types except null and undefined are treated as objects.

In Javascript, you can create your own Objects using the "Object Literal" or "Object Constructor" approach (where Object Contructors construct a Class of Objects that you can created your Objects from. Note: In this case, the Objects are not created directly - although you can use the Constructor structure to create Objects directly[1]). The "Name:Value" pair can be a "Name" and a "Function", where functions in Objects are called Methods.[2]. 

						
   myObjectLiteral = {                                        function MyObjectConstructor(firstName, familyName, age){
   	FirstName: Myles,                                          this.firstName = firstName;
   	familyName: Callan,                                        this.familyName = familyName;
   	age: 47,                                                   this.age = age;
     ... more Name:Value pairs ...,                            ... more Name:Value pairs ...;  
   	ageIn5Years = function(age){return age + 5;},              this.ageIn5Years = function(age){return age + 5;};
     ... more Methods ...,                                     ... more Methods ...; 
   }                                                          }

Convention dictates that Object constructor names begin with an uppercase letter (there is no reason to follow this convention, but it makes it easier to read your code, and acts as a reminder).

The Object Literal above is complete (i.e. ready to use). The Object Constructor merely contains placeholders for data to be added later. An Object is created from the Object Constructor var myObj1 = new MyObjectConstructor(Bartholomew, Guttersnipe, 112);.

In Javascript, the Object Values are retrieved using either "dot" notation or brackets ([ ]): Object.name or Object["name"]. Methods are called by myObject.method().

Just like functions, Objects are used to organize code - typically to group Name:Value pair into conceptual pieces (and, as with functions, they are also used to manage scope & closure (two related but separate concepts)).

Enumerating All Properties Of An Object

There are three native ways to list/traverse object properties:

  1. for...in loops
    This method traverses all enumerable properties of an object and its prototype chain
  2. Object.keys(o)
    This method returns an array with all the own (not in the prototype chain) enumerable properties' names ("keys") of an object o.
  3. Object.getOwnPropertyNames(o)
    This method returns an array containing all own properties' names (enumerable or not) of an object o.

The following example of a simple program highlights this process of using "for ... in loops" (and also highlights an important caveat). The for ... in loops for Objects works in the same way as it does for Arrays. That is, the combination of the keywords for and in tells the interpretor to enumerate the contents of the Object. However, as Objects don't have a natural index (unlike Arrays), the index relates to the names of each property. The caveat relates to obj.hasOwnProperty(i) ,

   	var result = "";
   	for (var i in obj) {                               ... so "i" are the names (as strings) of the properties in the Object obj ... 
   	   if (obj.hasOwnProperty(i)) { (this is the important caveat)
   	      result += objName + "." + i + " = " + obj[i] + "\n"; ... & "obj[i]" are the values of the properties in the Object obj ... 
   	      }
   	   }
   	   return result;

Since JavaScript functions are objects, they can have properties. A particularly important property that each function has is called prototype. prototype, which is itself an object, inherits from its parent’s prototype, which inherits from its parent’s prototype, and and so on. This is often referred to as the prototype chain. Object.prototype, which is always at the end of the prototype chain (i.e., at the top of the prototypal inheritance tree), contains methods like toString(), hasProperty(), isPrototypeOf(), and so on.

property lookups through the JavaScript prototype chain work as follows:

  1. If the object has a property with the given name, that value is returned. (The hasOwnProperty method can be used to check if an object has a particular named property.)
  2. If the object does not have the named property, the object’s prototype is checked
  3. Since the prototype is an object as well, if it does not contain the property either, its parent’s prototype is checked.
    4. This process continues up the prototype chain until the property is found.
  4. If Object.prototype is reached and it does not have the property either, the property is considered undefined.
Each property access therefore requires a dynamic look-up in that data structure to resolve the property. This approach makes accessing properties in JavaScript typically much slower
