Functions in Javascript

Overview

In most programming languages, a function is a series of commands grouped together (occasionally given specific parameters/arguments, (x) say) and given a name so that it can be called when needed. 

						
   function(){                                    function(x){
     ... commands ...       OR                     ... commands ... 
   }                                              }

Functions are used to organize code - typically to group code into conceptual pieces and/or to avoid repeating the same code (also to manage scope & closure (two related but separate concepts)).

The keyword for functions in Javascript is: function.

The main categories of functions in Javascript are: Function Expressions, Function Statements/Declarations, Higher-order Functions, & Immediately-Invoked Function Expressions (IIFE, pronouced iffy).

For a fuller understanding of the importance of these distinctions, an understanding of how your web browser processes Javascript is required.

JavaScript code is processed in two phases:

  • Phase 1: Compilation - in this phase the code is compiled into a syntax tree (and bytecode or binary depending on the engine).
    By default all variables created during this phase have the value of undefined (as it is presumed that some variables will require code to be interpreted to assign a value to them) and all declared functions are compiled.
  • Phase 2: Execution - the parsed code is then interpreted.
    The parsed code is typically interpreted line by line (apart from calls to declared functions, loops, and other changes to flow).

Categories of Functions

With this in mind, we can return to the categories of functions:

  1. Function Expressions create a function value: 
    						
   var f = function(){
   	 .. function statements ...
   };
    where f is the function value (Note: semi-colon).
  2. Function Declarations declare a variable and give it a function as its value: 
    						
   function g(){
   	 .. function statements ...
   	 }
    where g is declared to be a function (Note: no semi-colon).

    Note: Expressions, unlike declarations, are processed in the execution phase rather than the compilation phase. And because of this the order of expressions matter.

    That is, a function declaration can be called anywhere in your code, regardless of where the declaration is made - it is hoisted in the compilation phase. However, in either case, what you end up with is an identifier for a function, that you can invoke by putting parens (parentheses, ()) after it, like f(); or g();, in the cases above.



  3. Higher Order Function creates functions within a function: 
    						
   function h(){ 
     var z = 5; 
   	 function i(){
  	 ... i's function statements ...
     }
 	 ... h's other function statements ...
   }
    where the function i is a higher order function (which has access to h's local scope - in this case, z).
  4. Immediately-Invoked Function Expressions. create a function value: 
    						
   (function() {
   	someFunction() or someStatments;
   	}
   	)();
   or   
   (function() {
   	someFunction() or someStatments;
   	}
   	());

    The point of the parens, i.e. parenthesis ( ), or coercing operators, is to differentiate between function expressions and function declarations. The most widely accepted way to tell the parser to expect a function expression (and not a declaration) is just to wrap it in parens because, in JavaScript, parens can’t contain statements. So, when the parser encounters the function keyword, it knows to parse it as a function expression and not a function declaration. Therefore parens indicate that the function expression will be immediately invoked, and the variable will contain the result of the function, not the function itself. Since the anonymous function within our IIFE is a function expression and is not being assigned to a global variable, no global property is being created, and all of the properties created inside of the function expression are scoped locally to the expression itself (which will be explained in more detail later).

    So, what is the benefit of using IIFEs?

    Modularization! This is simply an extension of the idea behind a function, which was, in part, to group statements together that have a common context (and to avail of local scope to avoid name collisions - which are likely to occur if you are using Javascript code from a range of sources). A module is a collection of logically grouped functions. The primary purpose of these modules is to hide the implementation details of functions and to provide an entry point [or API] to provide an access these functions from outside.

Flow Control and Call Stack

A declared function is compiled during the compilation phase. It is not interpreted until it is called. Thus, when a declared function is called, the interpreter "jumps" to the compiled function, interprets its statements, then jumps back to where it was called. This is an example of Flow Control. The order of interpreted statements is managed by the Call Stack.

The following example of a simple program highlights this process. We see that there is a declared function, which is compiled in the first phase. After the interpreter completes the ... other statements ... , the greet function is called: greet("Harry");. At which point, the interpreter moves to the compiled declared function and interprets its statements. Once completed, the interpreter moves back to where the declared function was called. The interpreter does this by remembering where it was when it moved to the compiled function by noting it in the Call Stack: 


						
   function greet(who) {
      console.log("Hello " + who);
   }
   ... other statements ... 

   greet("Harry"); 
   console.log("Bye");

That is, the call to greet causes control to jump to the function. Then control moves to console.log in the greet function. Once that statement is interpreted, control has reached the end of the function, so control is then returned to the place that called the function.

Functions and Scope

Functions are unique in Javascript in that their block (of code) is the only place where local scope can be created.[1] We can think of "scope" as another word for "visible" or "accessible". So that, the variables created inside of function blocks, including their parameters, are local (visible or accessible) to that function alone. Wheras, all variables outside of local scope are visible globally.

That is, by default, all variables in Javascript have global scope except those created within functions

Understanding how scope is assigned brings us back to the two execution phases of a Javascript process. Scope is assigned by execution contexts:

  • Global context, created when a JavaScript process is launched
  • Local context, created when a function is invoked

Execution contexts are organized into a stack. At the bottom of the stack, there is always the global context, that is unique for each JavaScript program. Each time a function is encountered, a new execution context is created and pushed onto the top of the stack. Once the function has finished executing, its context is popped off the stack.

Within each execution context is a special object called a scope chain which is used to resolve variables - beginning with the most immediate context, ending with the global context. More generally, scope can be thought of as the set of rules for storing variables in some location, and for finding those variables at a later time. If variables have local scope, they can only be "found" within the function that they are defined in.

The lookup operations we’ve described in this example, whether based on the prototype chain or the scope chain, are repeated every time a property or variable is accessed. When this lookup occurs within loops or other intensive operations, it can have significant JavaScript performance ramifications, especially in light of the single-threaded nature of the language which prevents multiple operations from happening concurrently.

When we have higher order functions (functions within functions) we have nested scope. That is, the internal function has access to the outer function's local scope (and all variables already interpreted, and so defined, with global scope) but has its own local scope that is not accessible outside it. 

						
   // Scope A: Global scope out here
   function myFunction() {
   // Scope B: Local scope in here (for variables created in here)
   }

   // Scope A: Global scope out here
   function myFunction() {
      // Scope B: Local scope in here (for variables created in here)
      function myOtherFunction(){
      // Scope C: Nested Local scope in here (where Scope B is accessible) 
      // aka  Lexical Scope or Closure
      }
   }
