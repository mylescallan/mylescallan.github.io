HTML, CSS & Javascript: An Overview


All but the most basic webpages are constructed using a combination of HTML, CSS & Javascript.[1] This webpage will give you an overview of these "tools."

Introduction

HTML, CSS & Javascript: An Overview

To ensure that all browsers show webpages in a consistent way, there are standards/rules that creators of webpages follow.

HTML provides the standard for the structure of a webpage, CSS provides the standard for the presentation/style of a webpage, and Javascript provides the standard for actions that can be taken on a webpage.

HTML, CSS & Javascript are written in simple plain text.[2] They are scripts that interact to tell a computer how to compose a webpage, and what actions can be performed on that webpage.

The most basic way to view HTML is as a set of "tags" that designate where each part of your page should reside. It turns out that these "tags" are actually Objects that provide developers of webpages extraordinary control over a webpage (explaining this sentence is one of the key goals of this webpage). Thus, to be exact, we can say: The structure of a webpage provided by HTML is based on the Document Object Model (DOM). [3]

The presentation/style of CSS involves using the tags/Objects of HTML, in combination with short-hand instructions, to tell the browser how to format those elements (including, occasionally, where to position elements of a webpage).

Javascript provides the actions that you can perform on a webpage. A Javascript program does this by accessing the tags/Objects of HTML (and, occasionally, interacting with CSS).

HTML, CSS & Javascript: How They Work

The web browser that you are using to view this page is an application that interprets plain text files that it downloads from the web. The standards developed allow your browser to display webpages in consistent ways - that is, the page that you are looking at will look exactly the same to someone else (even if they are using a different browser and/or a different operating system).

HTML

By accessing the console window of your browser ("command+option+u", on a mac, or F12 on a windows computer), you can see the structure of this webpage. Initially it looks like a complicated mess of odd notation. Once you get used to it, you will see that it is a very structured set of symbols (with shorthand that is intuitive and easy to follow).[4]

For example, the viewable part of a webpage is written between a pair of <body> ... content here ... </body> tags. Where the "/" signifies the "closing" tag. Also, you can signify different "sections" of your webpage by placing the content between a pair of <section> ... this section's content here ... </section> tags. I am currently writing this paragraph between a pair of <p> ... this paragraph's content here ... </p> tags ("p" for paragraph). Image files are placed in an <image src="images/image.jpg"> tag. Media files can be placed between <media> ... audio/video content here ... </media> tags. And so on. Each of these tags ( <body>, <section>, <img>, <media> & <p> ) are examples of the standard HTML code used in every webpage.

CSS

CSS is used to "style" a webpage.

You can "style" your entire webpage by writing CSS for the Body of your webpage. In which you can specify: the font to be used, the background color (or image), the text color, the size of the margins around the page, and so on. To do this, your CSS file would look like this: 

     body {
        font-family: 'Quattrocento Sans', sans-serif;
        background-color: white;
        color: black;
        margin: 5em 10em 5em 10em;
        padding: 0em;
     }

"body" tells your browser that you want to style the body, the "{" encloses the style options, and then you list the options. That's all.

Obviously, you can have more complex styling. If, for example, you want a particular part of your webpage to be styled differently from the rest of the page you can use "id" or "class" attributes in your HTML tags. For example: <p id='id1' class='class1' > ... this paragraph's content here ... </p>, tells your browser that this paragraph has an id of 'id1' and a class name of 'class1'.[5] You would then add to your CSS file the specific styles that you want to apply to that particular part (or parts) of your webpage. Like so: 

     p.class1 {
        background-color: black;
        color: white;
     }

Where the "p" signifies "paragraph tag" and the ".class1" signifies the paragraphs with the "class1" attribute (p#id1 would be used if you wanted to style the paragraph with the "id1" id - that is, "." for classes and "#" for ids).[6].

Every feature of a webpage that is placed between tags, i.e. all features of a webpage, can be styled by CSS in this way.

Javascript

Javascript is a true programming language. Whereas HTML & CSS are scripts that provide shorthand to give instructions to a computer's browser, Javascript, despite its name, is a fully featured programming language (it started life as a programming language for browsers but can be used for programs that are independent of browsers).[7]

As with any programming language, Javascript is written in a text file and forms a list of instructions. Those instructions are interpreted by your browser.[8]

The most obvious question to ask is: What can Javascript instruct a browser to do? The answer to this is provided by the answer to another, related question: What features of a webpage can Javascript operate on? The answer is provided by HTML's Document Object Model. That is, Javascript provides intructions to your browser that allows you to extend the functionality of a webpage by operating on the Objects of a HTML document.

So far we have seen HTML's Document Object Model merely as a list of tags that gives structure to a webpage - both in terms of placement of the various parts of a webpage and as demarcation areas for CSS to style. Javascript allows us to dig a little deeper to see the real power of this model. Let's being with an example, one that involves an Object from HTML5 called a "canvas". [1] The most basic webpages can be written using HTML alone. More complicated webpages use extra "tools" (for example, a webpage that uses databases will, typically, also use php and mySQL).

[2] The HTML, CSS, & Javascript for a particular webpage are usually written in seperate text files. The HTML page will then contain links to the CSS & Javascript files and process them. This is all done in the background, without you doing anything or even being aware that it is happening.

Both CSS & Javascript code can be included directly in the HTML page but it is not the typical approach. CSS can be included directly on a page by placing it between <style> css code here </style> tags. The same is true of Javascript code - except that Javascript code written directly in a HTML page is placed in "script" tags, like this: <script> javascript code here </script>.

To get your browser to link my CSS file to this HTML file, I have this statement in the head of this page that you are reading: <link rel='stylesheet' type='text/css' href='css/gameDesignIntroduction.css'>. Similarly, I provide a link to the Javascript file, this time just before the closing "body" tag, like so: <script src="js/gameDesignIntroduction.js"></script>

[3] To see the structure of this webpage, i.e. the HTML used, you can view it directly using "command+shift+u", on a mac, or F12 on a windows computer. This brings up the "console" window of your brower. Different browsers have different setups for their console windows. They all have a feature called "Inspect" or "Inspector". Using this feature, if you double-click on part of the webpage it will: a) highlight that part of the webpage, and b) show you where that part of the webpage is in the "source code." Another feature of console windows is a tool that allows you to type commands or to see hidden output of a webpage. We will use this console window repeatedly, as it allows you to see, directly, the components of a webpage that I am explaining.

[4] One reason that the Inspector component of the console window is more useful than looking directly at the source code itself (i.e. the text file containing the HTML for this page) is that you can see clearly that the "tags" of HTML are more than just placeholders. Each tag in the inspector has a small grey "arrow" beside it. Clicking on those arrows opens the tag. Which, typically, reveals a range of other tags embedded in the original tag that you "opened". These "tags", as I mentioned before, are the Objects of the Document Object Model that provides the structure of a webpage. We will explore other features of these Objects later, which will allow you see the enormous amount of work that a browser does behind the scenes using these Objects (and the amazing control that these Objects give webpage designers over a webpage).

[5] You choose the names that you use for your ids and class names, and it is best to choose names that remind you why you are singling a section of the webpage out for special treatment. "id"s are unique identifiers whereas "classes" are used to indentify a group. So, if you want a style to be applied to one single part of your webpage you would use an "id", if you wanted a style to be applied to a broad range of your webpage contents, say all paragraphs in the first section, then you would give all of your paragraphs in the first section the same classname.

[6] To be clear, here are the most important options:

1) Style ALL paragraphs (just use "p" alone): 
     p {
        background-color: black;
        color: white;
     }
2) Style paragraphs with a particular class attribute (use "p" dot "classname"): 
     p.class1 {
        background-color: black;
        color: white;
     }
3) Style A paragraph with a particular id attribute (use "p" hash "id"): 
     p#id1 {
        background-color: black;
        color: white;
     }
